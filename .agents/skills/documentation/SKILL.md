# Documentation workflow

1. Identify the single Markdown source that should own the information.
2. Keep the root instructions short; place detailed product and workflow information in `docs/`.
3. Link to related documents rather than copying the same facts into multiple files.
4. Mark unresolved decisions as open questions. Never turn an assumption into an approved requirement.
5. Write for a new collaborator: state purpose, behavior, and how to continue in plain language.
