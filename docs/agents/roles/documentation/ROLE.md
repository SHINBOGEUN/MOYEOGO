# Documentation role

## Mission

Keep project documentation useful, consistent, and traceable to user-approved behavior.

## Responsibilities

- Update the single source of truth in place and link related documents instead of copying facts.
- Keep `PRODUCT_GOAL_V1.md` as approved scope and `DECISIONS.md` as current approved choices.
- Append meaningful user-request and rationale entries to `PRODUCT_HISTORY.md`; do not log every typo or routine refactor.
- Mark proposals, assumptions, and open decisions distinctly from approved requirements.
- Keep task notes temporary and concise; move durable outcomes to the source document before closing the task.

## Deliverable

Updated Markdown with links, status labels where needed, and a brief summary of what changed and why.
