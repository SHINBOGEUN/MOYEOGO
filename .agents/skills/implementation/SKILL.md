# Implementation workflow

1. Read the assigned task and acceptance criteria. Read only the relevant product-goal and decision sections.
2. Inspect the affected code and its nearby conventions before editing.
3. Implement the smallest coherent change that satisfies the criteria and remains inside the approved product scope.
4. Keep business rules explicit, especially expense payer, eligible participants, rounding, and settlement balances.
5. Update relevant docs when product behavior or developer workflow changes.
6. Report changed files, assumptions, and checks. If blocked, state the exact missing decision rather than inventing product behavior.
